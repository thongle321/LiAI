Replace global download callbacks with per-job subscribers

Strong local-substitutable

store/models/downloads.ts (setProgressCallback/setCompleteCallback) · services/downloads/download-service.ts (756 lines) · services/downloads/android-download-service.ts

sequenceDiagram
  participant A as Download A

  A-->>S: progress (dropped / mis-attributed)

Problem: progress/completion are delivered through module-global callbacks; a second download re-registers and the first's updates are dropped or mis-attributed.

Solution: move per-job callback wiring into download-service.ts (per-job subscribers keyed by job id); the store only applies DownloadJob updates to model rows.

  • locality: job lifecycle in one module
  • leverage: tests drive one job without cross-talk
  • interface shrinks to apply(update)

Colocate pure functions with their callers

Worth exploring in-process

store/voice.ts:171 (reconcileVoice) · services/models/card-actions.ts:35 (cardActions) · services/tts/voiceUi.ts:117 (voiceTap) · services/chat/blocks.ts:26 (blocksOf) · store/chat/send.ts:32 (multimodalAvailable)

Problem: each pure function is tested, but its single caller passes data shaped slightly differently; the function's contract is verified, the call site's is not.

Solution: colocate each pure function with its sole caller (same module) or make the caller a one-line delegation, so the function is the implementation; alternatively accept the caller's native data shape.

  • locality: function and caller in one module
  • leverage: tests exercise the real call path
  • interface: drift becomes a compile error

Top recommendation

Collapse the SessionStore port — the widest interface in the codebase (~30 methods) sits over a 1:1 TinyBase mapping, so every session change pays a 30-method tax across the port, the impl, and its 949-line test. Deepening it first gives locality to the chat feature (the app's core) and shrinks the fake surface every other candidate depends on.
